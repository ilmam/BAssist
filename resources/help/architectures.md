## What it is

An **architecture** model describes the system with C4 views (Context, Container, Component) for stakeholder communication and Structurizr export.

## How it fits

Architecture sits under **Diagrams**. It shows structure while state and swimlane flows show behaviour and process.

## Guidance

- Start with Context before diving into containers and components.
- Keep names aligned with how stakeholders talk about the system.
- Update the model when scope or integration decisions change.
